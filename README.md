# Дневник смен водителя

Мини-приложение для просмотра поездок и сводки за выбранный день. Бэкенд использует только стандартную библиотеку Python; данные хранятся в `data/trips.json`. Интерфейс адаптирован для узкого экрана, позволяет переключать даты и добавлять поездки.

## Запуск

Нужен Python 3.10 или новее. В каталоге проекта выполните:

```bash
python app.py
```

Откройте <http://127.0.0.1:8000>. Чтобы запустить на другом порту, задайте переменную окружения `PORT`; для другого файла хранения — `TRIPS_FILE`.

## API

- `GET /api/trips?date=2026-10-01` возвращает поездки, начинающиеся в выбранный календарный день, и сводку.
- `POST /api/trips` добавляет поездку. Тело JSON: `id`, `start`, `end`, `amount`, `payment` (`cash` или `card`), `commission`.

Для POST обязательны ISO 8601 timestamps с часовым поясом; сумма — целое число больше нуля, окончание — позже начала, комиссия — целое неотрицательное число. Повторный запрос с тем же ID и теми же данными возвращает `200` без создания записи. Повторное использование ID с другим содержимым возвращает `409`.

Пример:

```bash
curl -X POST http://127.0.0.1:8000/api/trips \
  -H 'Content-Type: application/json' \
  -d '{"id":"t3","start":"2026-10-01T10:00:00+05:00","end":"2026-10-01T10:20:00+05:00","amount":1800,"payment":"cash","commission":270}'
```

## Тесты

```bash
python -m unittest discover -s tests -v
```

Время в API должно содержать смещение часового пояса. Клиент сохраняет локальное смещение, чтобы поездка не попадала в соседний день после преобразования в UTC.

Тесты проверяют пример расчёта (3 900 ₸ выручки, 585 ₸ комиссии, 3 315 ₸ на руки), фильтрацию и хронологическую сортировку, валидацию и защиту от повторного добавления. HTTP-обработчики проверяются через in-memory соединение без открытия сетевого порта; отдельно проверены статусы `201`, `200`, `400` и `409`.

## Границы прототипа

JSON-файл и блокировка рассчитаны на один процесс сервера. Для нескольких экземпляров сервиса хранение следует перенести в базу данных и обеспечить уникальность ID на уровне БД. В прототипе нет аутентификации и внешнего платёжного контура.

## Как использовался ИИ

ИИ помог подготовить каркас API, адаптивный интерфейс и тестовые сценарии. При проверке обнаружено смещение времени на UTC относительно исходного `+05:00`; преобразование исправлено. Также вручную проверены валидация, поведение повторного ID и расчёт сводки на примере.
